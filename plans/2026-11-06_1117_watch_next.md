# Plan: "Seguir viendo" en el hero (Watch Next + fallback)

Fecha: 2026-11-06 11:17
Rama: `feat/watch-next` (desde `master`)

## Objetivo
El hero superior muestra contenido "Seguir viendo" (canal Watch Next de
Android TV, donde apps como Netflix publican contenido a medias) y, si no hay
datos, la app más recientemente lanzada como sugerencia.

## Diseño

### Nativo (Kotlin, `MainActivity.kt`)
- Sin dependencias nuevas: se consulta el content provider
  `content://android.media.tv/watch_next_program` leyendo las columnas por
  nombre (tvprovider 1.1.0 exige AGP 8 y el 1.0.0 no expone `fromCursor`;
  las columnas son estables desde API 26).
- `getWatchNextPrograms`: query a `TvContractCompat.WatchNextPrograms`
  (content provider estándar, sin permiso). Devuelve lista de mapas:
  title, intentUri, progress (0..1 calculado de lastPosition/duration),
  poster (ByteArray, decode del `content://` posterArtUri, reescalado a
  máx 960px de ancho, JPEG 80). try/catch → lista vacía.
- `launchIntentUri(String)`: `Intent.parseUri(URI_INTENT_SCHEME)` +
  startActivity. try/catch → false.

### Dart
- `flauncher_channel.dart`: `getWatchNextPrograms()`, `launchIntentUri()`.
- `lib/providers/watch_next_service.dart` (ChangeNotifier): `refresh()` al
  iniciar; expone `List<WatchNextItem>`. Registrado en `FLauncherApp`.
- Recientes (fallback): `SettingsService.recentPackages` (StringList prefs,
  máx 5, más reciente primero) + `addRecentPackage()`. `AppsService` recibe
  `SettingsService` via `ChangeNotifierProxyProvider` y registra en
  `launchApp`.
- `ContextualHero` (prioridad):
  1. Hero enfocado + hay item watch-next → muestra el item (póster, título,
     barra de progreso, label "Seguir viendo").
  2. App enfocada (FocusedAppService) → comportamiento actual.
  3. Hay item watch-next → lo muestra.
  4. Fallback: última app reciente (ícono + nombre + label "Reciente").
  5. Nada → shrink (comportamiento actual).
  El hero pasa a ser enfocable solo en modos 1/3/4; OK lanza el deep link
  (intentUri) o la app reciente.

## Riesgos / notas
- Watch Next solo tiene datos si las apps publican (Netflix sí, muchas no):
  de ahí el fallback.
- El póster llega como `content://`: se decodifica nativo, Flutter recibe bytes.
- No se puede probar end-to-end sin dispositivo/emulador TV; la lógica Dart
  queda cubierta por tests, lo nativo queda acotado y defensivo (try/catch).
